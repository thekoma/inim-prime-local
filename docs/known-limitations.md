# Known limitations

Honest boundaries of this integration.

- **Supported firmware: 4.x and 5.00.** Names, zone settings and scenario definitions are read from the panel's memory, whose map is specific to each firmware family. On another family setup stops with *firmware not supported* rather than guessing.
- **No event log on 5.00.** The event log's location in the 5.00 memory map is not known yet, so the *get event log* action fails there; it works on 4.x.
- **Command answers are undocumented.** The panel's answers to commands carry no documented success code. A command the panel silently refuses is noticed through the state re-read (a bypass the panel does not apply is reported as such), and a command whose answer is lost is reported as *may have reached the panel* rather than retried. Before arming, the zones that matter are read live and the arm is refused with *zones not ready* while one is open; tamper, faults and alarm memory are not checked, and no user code or PIN is sent. See [native-commands.md](native-commands.md).
- **Some scenarios cannot be applied.** A scenario is sent as one command setting each of its areas to one mode. A scenario with a combined target (e.g. an area set to both away and stay), or any scenario on a panel with areas beyond 0–11 (scenario definitions are only decoded that far), is refused with *scenario not supported*.
- **Output switches are hidden by default.** Outputs can drive sirens or other devices: enable only the ones you need. An output's on/off state follows Prime/STUDIO's rule (the terminal's value byte above 0), but an output switching on has not been observed on a live panel yet. Only the panel's own outputs are listed; outputs on expansion terminals are not.
- **Panel programming changes need a reload.** Which areas, zones, scenarios and outputs exist, and their names, are read once at setup. After adding, removing or renaming objects in PrimeStudio, reload the integration.
- **Realtime push is a one-time manual setup.** Instant updates use the panel's event-action ("Invio pagine web") table, which you configure once in PrimeStudio (see [realtime.md](realtime.md)). There is no API to program those entries automatically, so without that setup the integration relies on its 2 s poll.
- **Fault decomposition follows Prime/STUDIO.** The per-fault binary sensors use the bits Prime/STUDIO's monitoring page shows for the system status. They were verified live with no fault present; not every fault bit has been seen set on a live panel. The aggregate **System fault** sensor is the reliable headline.
- **No `siren` entity.** A siren is driven by the panel's own alarm logic, so there is no Home Assistant `siren` entity. If a siren is wired to a panel output (e.g. an output named *Sirene*), that output appears as an output switch like any other, hidden by default. You also get the siren's **anti-sabotage / supervision line** as a `tamper` `binary_sensor` (e.g. *AS Sirena Ext.*), and the *"alarm is sounding"* condition via the area `alarm_control_panel` going **triggered**.
- **Zone device class: the panel configuration first, then the label.** Wired INIM zones have no door / window / motion field, so the integration reads what the panel programming does say, natively at setup: a **fire** zone, a **roller-shutter** detector ("Tapparella": a cord pulley counted in pulses, so it senses the shutter *moving*, not whether it is open — shown as *moving* with shutter icons) and a **shock** detector ("Inerziale") are set from the configuration whatever the name. Otherwise the icon is guessed from the zone name (window, door, garage, motion, smoke, gas, CO, water, vibration, tamper). When the name says nothing, weaker configuration hints fill in: fault / hold-up zones → problem / safety, a 24-hour zone → tamper, an interior zone → motion, a delayed or chime zone → door. A window and an internal door are wired and programmed identically, so only the name tells them apart — if a zone gets the wrong icon, override the **device class** on the entity in Home Assistant.
- **Renaming is forward-looking for `entity_id`s.** The panel **Name** (set at setup, editable via *Reconfigure*) and the per-room device grouping drive the **device and friendly names**. Home Assistant never auto-renames an existing `entity_id`, so a panel first added under an older version (when the entity_id was derived from the IP) keeps those `entity_id`s until you rename the entities — or remove and re-add the integration — even though the friendly names update immediately.
- **No automatic discovery.** INIM panels don't advertise themselves on the network, so you enter the host manually (no mDNS/SSDP/DHCP discovery).
- **Prime / PrimeX only.** This integration speaks the Prime native protocol. **SmartLiving / Nexus** panels use a different protocol — see the alternatives in the README.
- **Weak encryption on the LAN.** The native protocol is AES-encrypted with the LAN password as the key and a fixed IV. Keep the panel on a trusted LAN segment, change the factory password, and never expose TCP 6004 to the internet (see the security notes in the README).
- **In-Home-Assistant brand icon.** The custom INIM-style icon ships in this repo, but the icon shown *inside* Home Assistant comes from the official `home-assistant/brands` repository (a separate, core-only submission); until then HA shows a default icon.
